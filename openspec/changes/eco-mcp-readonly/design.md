# Design: eco-mcp-readonly

## Choices

- **Extend `handbook_mcp`, do not add a second server.** Mark's decision.
  One server, one `.mcp.json` entry for every spoke.
- **Read-only, enforced by the tool inventory.** The existing "Read-only"
  requirement stays and the `tools/list` scenario is extended to the new
  tools, so a write tool shows up as a failing test.
- **Roles and skills come from the handbook's own files.** The role definition
  from `docs/agents/`, the skill from `inventory/skills-register.yml`. Both are
  already the single source (agent-registry), so the tool adds no second copy.
- **The role lookup is thin.** It overlaps
  `read_doc('handbook','docs/agents/<name>.md')` and adds only name resolution
  and the unknown-name refusal; the how-to says so.
- **The skill lookup reads one fixed file.** `_guard_path` blocks `inventory/`
  and stays as it is; the lookup takes a skill name, never a path, and fetches
  the register itself through `_fetch`. Nobody may widen `_guard_path`.
- **Tests assert existence and structure, not wording**: a role has a
  `## Mandate` heading, a skill's slug is present. Role and skill text can be
  edited without breaking the test.
- **Not an identity or authorisation source.** The how-to says so; the
  closed-npub rule lives in the registry guardrails.
- **Factory status and wordsworth dossier search are follow-ups.**
  `handbook_mcp` only reads github.com through `_fetch`/`_guard_repo`; it has
  no access path to ratatoskr's state files or wordsworth's API.
- **New tool text is English** (repo invariant). The existing Dutch docstrings
  are not touched by this change.

## Rejected alternatives

- **A separate ecosystem MCP server.** Rejected by the decision to extend
  `handbook_mcp`.
- **Write tools in the first version** (queue a build, move a card). Rejected:
  "read-only first".
- **Keeping factory status and dossier search in this change.** No access
  path exists in `handbook_mcp`; they wait for follow-ups.
- **Widening `_guard_path` to include `inventory/`.** Weakens the path bound
  for every tool.

## Risks

- The register is generated by `forge register`; its format can change under
  the tool. The test asserts structure (slug present), not content.
